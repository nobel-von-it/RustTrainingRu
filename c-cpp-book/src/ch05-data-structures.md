### Тип массива в Rust

> **Что вы узнаете:** Основные структуры данных Rust — массивы, кортежи, срезы, строки, структуры, `Vec` и `HashMap`. Это насыщенная глава; сосредоточьтесь на понимании разницы между `String` и `&str` и на работе структур. Мы подробно вернемся к ссылкам и заимствованию в главе 7.

- Массивы содержат фиксированное количество элементов одного типа
    - Как и все остальные типы в Rust, массивы неизменяемы по умолчанию (если только не используется mut)
    - Элементы массива адресуются с помощью квадратных скобок `[]` с обязательной проверкой выхода за границы. Метод `len()` возвращает длину массива

```rust
    fn main() {

        let a : [u8; 3] = [42; 3];
        // Альтернативный синтаксис
        // let a = [42u8, 42u8, 42u8];
        for x in a {
            println!("{x}");
        }
        let y = get_index(a.len());
        // Раскомментирование строки ниже приведет к панике
        //println!("{}", a[y]);
    }
```

### Кортежи в Rust
- Кортежи имеют фиксированный размер и могут объединять произвольные типы в один составной тип
    - К элементам кортежа можно обращаться по их индексам (.0, .1, .2, ...). Пустой кортеж `()` называется единичным типом (unit type) и является аналогом возвращаемого значения `void`
    - Rust поддерживает деструктуризацию кортежей, что позволяет легко привязывать переменные к отдельным элементам
```rust
fn get_tuple() -> (u32, bool) {
    (42, true)        
}

fn main() {
   let t : (u8, bool) = (42, true);
   let u : (u32, bool) = (43, false);
   println!("{}, {}", t.0, t.1);
   println!("{}, {}", u.0, u.1);
   let (num, flag) = get_tuple(); // Деструктуризация кортежа
   println!("{num}, {flag}");
}
```

### Ссылки в Rust
- Ссылки в Rust концептуально похожи на указатели в C, но имеют ряд ключевых отличий
    - Разрешено иметь любое количество ссылок только для чтения (неизменяемых ссылок) на переменную в любой момент времени. Ссылка не может пережить область видимости самой переменной (это фундаментальное понятие в Rust называется **временем жизни**; подробно рассматривается далее)
    - Разрешена только одна ссылка с возможностью записи (изменяемая ссылка) на изменяемую переменную, и она не должна сосуществовать с какими-либо другими ссылками.
```rust
fn main() {
    let mut a = 42;
    {
        let b = &a;
        let c = b;
        println!("{} {}", *b, *c); // Компилятор автоматически разыменовывает *c
        
        let d = &mut a;
        
        /*
         * Раскомментирование строки ниже приведет к ошибке компиляции,
         * так как ссылка `b` используется в то время, как изменяемая
         * ссылка `d` все еще активна в текущей области видимости.
         * 
         * Нельзя одновременно использовать изменяемую и неизменяемую ссылки
         * в одной и той же области видимости!
         */
        // println!("{}", *b);
    }
    let d = &mut a; // Отлично: b и c вышли из области видимости
    *d = 43;
}
```

# Срезы (slices) в Rust
- Ссылки в Rust могут использоваться для создания подмножеств массивов (срезов)
    - В отличие от массивов, которые имеют фиксированную длину, определяемую на этапе компиляции, срезы могут быть произвольного размера. Внутри срезы реализованы как «толстый указатель» (fat pointer), который хранит длину среза и указатель на начальный элемент в исходном массиве
```rust
fn main() {
    let a = [40, 41, 42, 43];
    let b = &a[1..a.len()]; // Срез, начинающийся со второго элемента исходного массива
    let c = &a[1..]; // То же самое, что и выше
    let d = &a[..]; // То же самое, что и &a[0..] или &a[0..a.len()]
    println!("{b:?} {c:?} {d:?}");
}
```

# Константы и статические переменные в Rust
- Ключевое слово ```const``` используется для определения константных значений. Константы вычисляются на **этапе компиляции** и встраиваются (inlined) непосредственно в код программы
- Ключевое слово ```static``` используется для определения аналога глобальных переменных. Статические переменные имеют фиксированный адрес в памяти, создаются один раз и существуют в течение всего времени работы программы
```rust
const SECRET_OF_LIFE: u32 = 42;
static GLOBAL_VARIABLE : u32 = 2;
fn main() {
    println!("The secret of life is {}", SECRET_OF_LIFE);
    println!("Value of global variable is {GLOBAL_VARIABLE}")
}
```

# Строки в Rust: String против &str

- В Rust есть **два** строковых типа, служащих для разных целей:
    - `String` — владеющий, размещаемый в куче, динамически расширяемый тип (аналог буфера `malloc` в C или `std::string` в C++)
    - `&str` — заимствованная ссылка (срез строки, аналогичный `const char*` с указанием длины в C или `std::string_view` в C++). Важное отличие: время жизни `&str` **строго проверяется**, поэтому ссылка никогда не станет висячей
    - В отличие от нуль-терминированных строк C, строки в Rust хранят свою длину и гарантированно содержат валидный UTF-8

> **Для разработчиков C++:** `String` ≈ `std::string`, `&str` ≈ `std::string_view`. В отличие от `std::string_view`, валидность ссылки `&str` на протяжении всего ее времени жизни гарантируется проверкой заимствований (borrow checker).

## String против &str: владение против заимствования

> **Шаблоны в реальных проектах**: См. раздел [Обработка JSON: nlohmann::json → serde](ch17-2-avoiding-unchecked-indexing.md#json-handling-nlohmannjson--serde) для ознакомления с тем, как обработка строк работает с библиотекой serde.

| **Аспект** | **C `char*`** | **C++ `std::string`** | **Rust `String`** | **Rust `&str`** |
|------------|--------------|----------------------|-------------------|----------------|
| **Память** | Вручную (`malloc`/`free`) | Выделяется в куче, владеет буфером | Выделяется в куче, очищается автоматически | Заимствованная ссылка (с проверкой времени жизни) |
| **Мутабельность** | Всегда изменяемая по указателю | Изменяемая | Изменяемая при наличии `mut` | Всегда неизменяемая |
| **Информация о размере** | Нет (зависит от `'\0'`) | Хранит длину и емкость | Хранит длину и емкость | Хранит длину (толстый указатель) |
| **Кодировка** | Не определена (обычно ASCII) | Не определена (обычно ASCII) | Гарантированный валидный UTF-8 | Гарантированный валидный UTF-8 |
| **Нуль-терминатор** | Обязателен | Обязателен (`c_str()`) | Не используется | Не используется |

```rust
fn main() {
    // &str — срез строки (заимствованный, неизменяемый, обычно строковый литерал)
    let greeting: &str = "Hello";  // Указывает на память только для чтения

    // String — владеющая строка, выделяется в куче, может расширяться
    let mut owned = String::from(greeting);  // Копирует данные в кучу
    owned.push_str(", World!");        // Увеличивает строку
    owned.push('!');                   // Добавляет один символ

    // Преобразование между String и &str
    let slice: &str = &owned;          // String -> &str (бесплатно, просто заимствование)
    let owned2: String = slice.to_string();  // &str -> String (выделяет память)
    let owned3: String = String::from(slice); // То же самое, что и выше

    // Конкатенация строк (обратите внимание: оператор + поглощает левый операнд)
    let hello = String::from("Hello");
    let world = String::from(", World!");
    let combined = hello + &world;  // hello перемещается (поглощается), world заимствуется
    // println!("{hello}");  // Не скомпилируется: hello был перемещен

    // Используйте макрос format!, чтобы избежать проблем с перемещением
    let a = String::from("Hello");
    let b = String::from("World");
    let combined = format!("{a}, {b}!");  // Ни a, ни b не поглощаются

    println!("{combined}");
}
```

## Почему нельзя индексировать строки с помощью `[]`
```rust
fn main() {
    let s = String::from("hello");

    // Безопасные альтернативы:
    let first_char = s.chars().next();           // Option<char>: Some('h')

    let substring = &s[0..1];                    // &str: "h" (байтовый диапазон, должен проходить по границе UTF-8 символа)

    println!("Bytes: {:?}", &as_bytes[..5]);
}
```

# Структуры в Rust
- Ключевое слово ```struct``` объявляет пользовательский структурный тип
    - Члены ```struct``` могут быть либо именованными, либо анонимными (кортежные структуры)
- В отличие от таких языков, как C++, в Rust отсутствует понятие «наследования данных»
```rust
fn main() {
    struct MyStruct {
        num: u32,
        is_secret_of_life: bool,
    }
    let x = MyStruct {
        num: 42,
        is_secret_of_life: true,
    };
    let y = MyStruct {
        num: x.num,
        is_secret_of_life: x.is_secret_of_life,
    };
    let z = MyStruct { num: x.num, ..x }; // Запись .. означает копирование остальных полей
    println!("{} {} {}", x.num, y.is_secret_of_life, z.num);
}
```

# Кортежные структуры в Rust
- Кортежные структуры в Rust похожи на обычные кортежи, и их отдельные поля не имеют имен
    - Как и в кортежах, доступ к элементам осуществляется через .0, .1, .2, .... Распространенным сценарием использования кортежных структур является обертывание примитивных типов для создания собственных типов. **Это помогает избежать случайного смешивания различных по смыслу значений одного и того же типа**
```rust
struct WeightInGrams(u32);
struct WeightInMilligrams(u32);
fn to_weight_in_grams(kilograms: u32) -> WeightInGrams {
    WeightInGrams(kilograms * 1000)
}

fn to_weight_in_milligrams(w : WeightInGrams) -> WeightInMilligrams  {
    WeightInMilligrams(w.0 * 1000)
}

fn main() {
    let x = to_weight_in_grams(42);
    let y = to_weight_in_milligrams(x);
    // let z : WeightInGrams = x;  // Не скомпилируется: владение x было передано в to_weight_in_milligrams()
    // let a : WeightInGrams = y;   // Не скомпилируется: несоответствие типов (WeightInMilligrams против WeightInGrams)
}
```


**Примечание**: Атрибут `#[derive(...)]` автоматически генерирует реализации стандартных типажей для структур и перечислений. Вы будете часто видеть его использование на протяжении курса:
```rust
#[derive(Debug, Clone, PartialEq)]
struct Point { x: i32, y: i32 }

fn main() {
    let p = Point { x: 1, y: 2 };
    println!("{:?}", p);           // Debug: работает благодаря #[derive(Debug)]
    let p2 = p.clone();           // Clone: работает благодаря #[derive(Clone)]
    assert_eq!(p, p2);            // PartialEq: работает благодаря #[derive(PartialEq)]
}
```
Мы подробно рассмотрим систему типажей позже, но `#[derive(Debug)]` настолько полезен, что его рекомендуется добавлять практически к каждой создаваемой вами структуре (`struct`) и перечислению (`enum`).

# Динамический вектор Vec в Rust
- Тип ```Vec<T>``` реализует динамический буфер в куче (аналог массивов с ручным управлением `malloc`/`realloc` в C или `std::vector` в C++)
    - В отличие от массивов фиксированного размера, `Vec` может расти и уменьшаться во время выполнения программы
    - `Vec` владеет своими данными и автоматически управляет выделением и освобождением памяти
- Общие операции: `push()`, `pop()`, `insert()`, `remove()`, `len()`, `capacity()`
```rust
fn main() {
    let mut v = Vec::new();    // Пустой вектор, тип выводится из использования
    v.push(42);                // Добавление элемента в конец — Vec<i32>
    v.push(43);                
    
    // Safe iteration (preferred)
    for x in &v {              // Заимствуем элементы, вектор не поглощается
        println!("{x}");
    }
    
    // Способы быстрой инициализации
    let mut v2 = vec![1, 2, 3, 4, 5];           // Макрос для инициализации
    let v3 = vec![0; 10];                       // 10 нулей
    
    // Безопасные методы доступа (предпочтительнее прямой индексации)
    match v2.get(0) {
        Some(first) => println!("First: {first}"),
        None => println!("Empty vector"),
    }
    
    // Полезные методы
    println!("Length: {}, Capacity: {}", v2.len(), v2.capacity());
    if let Some(last) = v2.pop() {             // Удаляет и возвращает последний элемент
        println!("Popped: {last}");
    }
    
    // Опасно: прямой доступ по индексу (может вызвать панику!)
    // println!("{}", v2[100]);  // Вызовет панику во время работы
}
```
> **Шаблоны в реальных проектах**: См. раздел [Избегание непроверяемой индексации](ch17-2-avoiding-unchecked-indexing.md#avoiding-unchecked-indexing) для ознакомления с безопасными паттернами использования метода `.get()` в промышленном коде.

# Хэш-таблица HashMap в Rust
- ```HashMap``` реализует ассоциативный массив общего вида ```ключ``` -> ```значение``` (также известный как словарь или отображение)
```rust
fn main() {
    use std::collections::HashMap;  // В отличие от Vec, требуется явный импорт
    let mut map = HashMap::new();       // Выделение памяти под пустую HashMap
    map.insert(40, false);  // Тип выводится как целое число -> bool
    map.insert(41, false);
    map.insert(42, true);
    for (key, value) in map {
        println!("{key} {value}");
    }
    let map = HashMap::from([(40, false), (41, false), (42, true)]);
    if let Some(x) = map.get(&43) {
        println!("43 was mapped to {x:?}");
    } else {
        println!("No mapping was found for 43");
    }
    let x = map.get(&43).or(Some(&false));  // Значение по умолчанию, если ключ не найден
    println!("{x:?}"); 
}
```

## Глубокое погружение: ссылки в C++ против ссылок в Rust

> **Для разработчиков C++:** Программисты C++ часто предполагают, что ссылка `&T` в Rust работает так же, как `T&` в C++. Несмотря на внешнее сходство, между ними существуют принципиальные различия, вызывающие путаницу. Разработчики на C могут пропустить этот раздел — ссылки в Rust подробно описаны в главе [Владение и заимствование](ch07-ownership-and-borrowing.md).

#### 1. Отсутствие rvalue-ссылок и универсальных ссылок

В C++ символы `&&` имеют два разных значения в зависимости от контекста:

```cpp
// C++: && в зависимости от контекста означает разные вещи:
int&& rref = 42;           // rvalue-ссылка — привязывается к временным объектам
void process(Widget&& w);   // rvalue-ссылка — вызывающая сторона должна использовать std::move

// Универсальная (пересылающая) ссылка — контекст выведения шаблона:
template<typename T>
void forward(T&& arg) {     // НЕ является rvalue-ссылкой! Выводится как T& или T&&
    inner(std::forward<T>(arg));  // Идеальная передача (perfect forwarding)
}
```

**В Rust ничего подобного нет.** Оператор `&&` — это просто логическое И.

```rust
// В Rust && — это просто логическое И
let a = true && false; // false

// В Rust НЕТ rvalue-ссылок, универсальных ссылок и идеальной передачи.
// Вместо этого:
//   - Перемещение является поведением по умолчанию для типов, не реализующих Copy (std::move не нужен)
//   - Обобщения + ограничения типажей заменяют универсальные ссылки
//   - Нет различия для временных привязок — значения остаются значениями

fn process(w: Widget) { }      // Принимает владение (как передача по значению в C++ + неявный move)
fn process_ref(w: &Widget) { } // Заимствует неизменяемо (как const T& в C++)
fn process_mut(w: &mut Widget) { } // Заимствует изменяемо (как T& в C++, но монопольно)
```

| **Концепция C++** | **Эквивалент в Rust** | **Примечания** |
|-------------|-----------------|-------|
| `T&` (lvalue-ссылка) | `&T` или `&mut T` | В Rust разделяется на разделяемую (shared) и монопольную (exclusive) |
| `T&&` (rvalue-ссылка) | Просто `T` | Передача по значению = передача владения |
| `T&&` в шаблоне (универсальная ссылка) | `impl Trait` или `<T: Trait>` | Обобщения заменяют передачу |
| `std::move(x)` | `x` (просто используйте переменную) | Перемещение по умолчанию |
| `std::forward<T>(x)` | Эквивалент не требуется | Нет универсальных ссылок, требующих передачи |

#### 2. Перемещения являются побитовыми — никаких конструкторов перемещения

В C++ перемещение — это *определяемая пользователем операция* (конструктор перемещения / оператор присваивания перемещением). В Rust перемещение всегда представляет собой **побитовое копирование (memcpy)** значения, после чего исходная переменная инвалидируется:

```rust
// Перемещение в Rust = побитовое копирование, пометка источника невалидным
let s1 = String::from("hello");
let s2 = s1; // Байты s1 копируются в стековый кадр для s2
              // s1 теперь невалидна — компилятор строго следит за этим
// println!("{s1}"); // ❌ Ошибка компиляции: использование значения после перемещения
```

```cpp
// Перемещение в C++ = вызов конструктора перемещения (определенного пользователем!)
std::string s1 = "hello";
std::string s2 = std::move(s1); // Вызывает конструктор перемещения строки
// s1 теперь находится в «валидном, но неопределенном состоянии»
std::cout << s1; // Компилируется! Выводит... что-то (обычно пустую строку)
```

**Следствия**:
- В Rust нет «правила пяти» (не нужно определять конструкторы копирования и перемещения, операторы присваивания копированием и перемещением, а также деструктор)
- Отсутствует «зомби»-состояние у перемещенных объектов — компилятор просто запрещает обращаться к ним
- Нет необходимости заботиться об указании `noexcept` при перемещении — побитовое копирование физически не может выбросить исключение

#### 3. Автоматическое разыменование: компилятор видит сквозь косвенность

Rust автоматически выполняет разыменование через несколько уровней указателей/оберток с помощью типажа `Deref`. Аналогов в C++ для этого нет:

```rust
use std::sync::{Arc, Mutex};

// Сложная обертка: Arc<Mutex<Vec<String>>>
let data = Arc::new(Mutex::new(vec!["hello".to_string()]));

// В C++ вам потребовалось бы явно снимать блокировку и разыменовывать каждый уровень вручную.
// В Rust компилятор автоматически разыменовывает по цепочке Arc → Mutex → MutexGuard → Vec:
let guard = data.lock().unwrap(); // Arc автоматически разыменовывается в Mutex
let first: &str = &guard[0];      // MutexGuard→Vec (через Deref), Vec[0] (через Index),
                                   // &String→&str (приведение типов через Deref)
println!("First: {first}");

// Вызовы методов также автоматически разыменовываются:
let boxed_string = Box::new(String::from("hello"));
println!("Length: {}", boxed_string.len());  // Box→String, затем String::len()
// Нет необходимости писать (*boxed_string).len() или boxed_string->len()
```

**Приведение типов через разыменование (Deref coercion)** также работает для аргументов функций — компилятор автоматически добавляет разыменования для соответствия ожидаемым типам:

```rust
fn greet(name: &str) {
    println!("Hello, {name}");
}

fn main() {
    let owned = String::from("Alice");
    let boxed = Box::new(String::from("Bob"));
    let arced = std::sync::Arc::new(String::from("Carol"));

    greet(&owned);  // &String → &str (1 приведение типа)
    greet(&boxed);  // &Box<String> → &String → &str (2 приведения типа)
    greet(&arced);  // &Arc<String> → &String → &str (2 приведения типа)
    greet("Dave");  // Уже &str — приведение типов не требуется
}
// В C++ для каждого из этих случаев потребовалось бы вызывать .c_str() или делать явные преобразования.
```

**Цепочка Deref**: Когда вы вызываете `x.method()`, поиск метода в Rust
сначала пытается найти его для типа получателя `T`, затем для `&T`, а затем для `&mut T`.
Если соответствие не найдено, значение разыменовывается через типаж `Deref`, и процесс
повторяется для целевого типа. Так может продолжаться через несколько уровней — вот почему
`Box<Vec<T>>` «просто работает» аналогично `Vec<T>`. Приведение типов через `Deref`
(для аргументов функций) — это похожий, но отдельный механизм, который автоматически преобразует
`&Box<String>` в `&str`, выстраивая цепочку из реализаций `Deref`.

#### 4. Никаких null-ссылок и ссылок-указателей

```cpp
// В C++: ссылки не могут быть null, но указатели могут, и грань между ними размыта
Widget& ref = *ptr;  // Если ptr равен null → UB
Widget* opt = nullptr;  // «необязательная» ссылка через указатель
```

```rust
// В Rust: ссылки ВСЕГДА валидны — это гарантируется проверкой заимствований
// В безопасном коде нет возможности создать null или висячую ссылку
let r: &i32 = &42; // Всегда валидно

// «Необязательная ссылка» выражается явно:
let opt: Option<&Widget> = None; // Явное намерение, отсутствие null-указателя
if let Some(w) = opt {
    w.do_something(); // Выполняется только при наличии значения
}
```

#### 5. Ссылки нельзя перенаправить

```cpp
// В C++: ссылка является псевдонимом — ее нельзя переназначить
int a = 1, b = 2;
int& r = a;
r = b;  // Это ПРИСВАИВАЕТ значение b переменной a — это НЕ перенаправляет r!
// a теперь равно 2, r все еще ссылается на a
```

```rust
// В Rust: связывание через let поддерживает затенение, но у ссылок другие правила
let a = 1;
let b = 2;
let r = &a;
// r = &b;   // ❌ Нельзя присвоить значение неизменяемой переменной
let r = &b;  // ✅ Но вы можете ЗАТЕНИТЬ r новым связыванием
             // Старое связывание теряется, ссылка не перенаправляется

// С использованием mut:
let mut r = &a;
r = &b;      // ✅ r теперь указывает на b — это И ЕСТЬ перенаправление ссылки
```

> **Ментальная модель**: В C++ ссылка является постоянным псевдонимом объекта.
> В Rust ссылка — это значение (указатель с гарантированным временем жизни), которое
> подчиняется обычным правилам связывания переменных: оно неизменяемо по умолчанию и может быть
> перенаправлено, только если переменная объявлена как `mut`.
