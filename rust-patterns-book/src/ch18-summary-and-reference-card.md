## Краткий справочник

### Руководство по выбору паттернов

```text
Нужна типобезопасность для примитивов?
└── Паттерн Newtype (Ch3)

Нужен контроль состояний на этапе компиляции?
└── Паттерн состояний типов / Type-state (Ch3)

Нужен «тег» без данных времени выполнения?
└── PhantomData (Ch4)

Нужно разорвать циклы ссылок Rc/Arc?
└── Weak<T> / sync::Weak<T> (Ch8)

Нужно ожидать условие без активного ожидания (busy-loop)?
└── Condvar + Mutex (Ch6)

Нужно обработать «один из N типов»?
├── Известное закрытое множество → Перечисление (Enum)
├── Открытое множество, критический путь (hot path) → Обобщения (Generics)
├── Открытое множество, некритический путь (cold path) → dyn Trait
└── Полностью неизвестные типы → Any + TypeId (Ch2)

Нужно разделяемое состояние между потоками?
├── Простой счетчик/флаг → Атомики (Atomics)
├── Короткая критическая секция → Mutex
├── Частые чтения, редкие записи → RwLock
├── Ленивая однократная инициализация → OnceLock / LazyLock (Ch6)
└── Сложное состояние → Акторы + Каналы

Нужно параллелить вычисления?
├── Обработка коллекций → rayon::par_iter
├── Фоновая задача → thread::spawn
└── Заимствование локальных данных → thread::scope

Нужен асинхронный ввод-вывод (I/O) или конкурентная сеть?
├── Простые сценарии → tokio + async/await (Ch15)
└── Сложные (стримы, middleware) → см. Async Rust Training

Нужна обработка ошибок?
├── Библиотека → thiserror (#[derive(Error)])
└── Приложение → anyhow (Result<T>)

Нужно предотвратить перемещение значения?
└── Pin<T> (Ch8) — требуется для Futures, самоссылающихся типов
```

### Шпаргалка по ограничениям типажей (Trait Bounds)

| Ограничение | Смысл / Назначение |
|-------------|-------------------|
| `T: Clone` | Может быть продублирован (клонирован) |
| `T: Send` | Может быть передан в другой поток |
| `T: Sync` | Ссылка `&T` может безопасно разделяться между потоками |
| `T: 'static` | Не содержит нестатических ссылок |
| `T: Sized` | Размер известен на этапе компиляции (по умолчанию) |
| `T: ?Sized` | Размер может быть неизвестен (`[T]`, `dyn Trait`) |
| `T: Unpin` | Безопасно перемещать после пиннинга (pinning) |
| `T: Default` | Имеет значение по умолчанию |
| `T: Into<U>` | Может быть преобразован в `U` |
| `T: AsRef<U>` | Может быть заимствован как `&U` |
| `T: Deref<Target = U>` | Автоматически разыменовывается в `&U` |
| `F: Fn(A) -> B` | Вызываемый объект, заимствует состояние неизменяемо |
| `F: FnMut(A) -> B` | Вызываемый объект, может изменять состояние |
| `F: FnOnce(A) -> B` | Вызываемый объект ровно один раз, может потреблять состояние |

### Правила неявного вывода времен жизни (Lifetime Elision)

Компилятор автоматически подставляет времена жизни в трех случаях (чтобы вам не приходилось делать это вручную):

```rust
// Правило 1: Каждый ссылочный параметр получает свое собственное время жизни
// fn foo(x: &str, y: &str)  →  fn foo<'a, 'b>(x: &'a str, y: &'b str)

// Правило 2: Если есть ровно ОДИН входной параметр времени жизни, он используется для всех выходных
// fn foo(x: &str) -> &str   →  fn foo<'a>(x: &'a str) -> &'a str

// Правило 3: Если один из параметров &self или &mut self, используется его время жизни
// fn foo(&self, x: &str) -> &str  →  fn foo<'a>(&'a self, x: &str) -> &'a str
```

**Когда вы ОБЯЗАНЫ явно указывать времена жизни**:
- Наличие нескольких входных ссылок при возврате ссылки (компилятор не может угадать, от какого входа зависит выход)
- Поля структур, хранящие ссылки: `struct Ref<'a> { data: &'a str }`
- Ограничения `'static`, когда вам требуются данные, не содержащие заимствованных ссылок

### Распространенные автодеревации типажей (Derive)

```rust
#[derive(
    Debug,          // Форматирование {:?}
    Clone,          // .clone()
    Copy,           // Неявное копирование (только для простых типов)
    PartialEq, Eq,  // Сравнение на равенство ==
    PartialOrd, Ord, // Сравнение < > + сортировка
    Hash,           // Ключ для HashMap/HashSet
    Default,        // Type::default()
)]
struct MyType { /* ... */ }
```
